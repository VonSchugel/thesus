# Browser agents and orchestration research

Reviewed November 5, 2026. The decision concerns the Python browser workspace in this repository. Release activity, source behavior, published benchmark results, and practitioner reports answer different questions and are kept separate below.

## Existing code and decision

The starting workspace is a FastAPI application with async SQLAlchemy and SQLite, a Jinja and vanilla JavaScript interface, and per-branch execution tasks. It persists messages, events, approval requests, runtime state, and checkpoints. Branch creation copies the recorded history through the checkpoint. The deterministic planner creates subtasks, the navigator calls a browser adapter, and the extractor builds the user-facing summary. The loopback Ollama integration enriches completed findings separately from browser execution. Preserve the API vocabulary, data model, checkpoint/replay paths, fake-browser tests, and advisory separation. Extend the browser adapter boundary and the existing per-branch lock for real browser work. Add a typed model decision provider only where it can make a proposal for the host to validate.

The original real adapter creates a browser-use Agent for each subtask step. At the installed pin, an Agent step can contain five actions by default. Its callback receives the entire model output before the action batch. The local adapter records only the first action from that callback. After the callback, browser-use checks for cooperative interruption separately during batch iteration. This cannot guarantee that the displayed approval covers the action dispatched. The pinned Agent also stops the retained BrowserSession event bus on close. A single Playwright browser context per branch with one typed command at a time gives the workspace a direct boundary for dispatch, auditing, manual input, and exact approval validation. Keep a run checkpoint separate from the live Chromium process. [Pinned agent setup](https://github.com/browser-use/browser-use/blob/0.11.13/browser_use/agent/service.py#L175), [model callback](https://github.com/browser-use/browser-use/blob/0.11.13/browser_use/agent/service.py#L1679-L1697), [batch dispatch](https://github.com/browser-use/browser-use/blob/0.11.13/browser_use/agent/service.py#L2709-L2736), [close behavior](https://github.com/browser-use/browser-use/blob/0.11.13/browser_use/agent/service.py#L3921-L3938).

## Durable execution

- **Existing state machine and SQLite.** This is the lightest fit for one worker process. The critical invariant is a shared lock between browser commands and ownership transitions, plus a fresh observation after takeover, reconnect, or a stale revision. A completed click can have affected a remote system even when the local process crashes before recording the result. Persist dispatch intent and report ambiguous outcomes for review. Never automatically replay an uncertain external effect.
- **LangGraph.** MIT Python library, with 1.2.20 reported November 5, 2026. A checkpointer and thread ID support durable interrupts and replay. The interrupted node runs again from its beginning on resume. Durable-task extraction and idempotency still matter around external effects. An August 2026 preprint observed crash-time reexecution against version 1.2.9 under specific tests. It supplies a regression scenario and says nothing conclusive about 1.2.20. [Interrupt contract](https://docs.langchain.com/oss/python/langgraph/interrupts), [durable execution](https://docs.langchain.com/oss/python/langgraph/durable-execution), [source](https://github.com/langchain-ai/langgraph/tree/60cbb4af560d71fc5b9cd81dbb5ed46b5525d09b), [conformance preprint](https://arxiv.org/abs/2608.03836).
- **LlamaIndex Workflows.** MIT event-driven Python implementation. A workflow can emit an `InputRequiredEvent` and receive a `HumanResponseEvent`. This fits user prompts and workflow state. An application still needs to preserve browser identity, serialize input, and verify the effect after an interrupted connection. The monorepo main revision was a457071342dd1b0fe4eabb28ad80b73c9c4219c1. Its latest GitHub release marker referred to a package in the monorepo, so it cannot establish the Workflows package version. [Implementation](https://github.com/run-llama/llama-agents/blob/a457071342dd1b0fe4eabb28ad80b73c9c4219c1/packages/llama-index-workflows/src/workflows/workflow.py), [human input](https://developers.llamaindex.ai/python/framework/understanding/agent/human_in_the_loop/), [deployment](https://developers.llamaindex.ai/python/llamaagents/workflows/).
- **Temporal.** MIT Python SDK with durable workflow history, typed Signals/Updates, retries and explicit cancellation modes. Browser operations belong in activities against a separately owned browser worker, since deterministic workflow replay cannot reconstruct a live Chromium target or undo an external click. Retry requires idempotency or reconciliation. An SDK issue contains a reproducer for an activity cancellation and acknowledgment race. Service and worker administration are additional operational costs. Temporal becomes a strong candidate when work must survive multiple workers or run across hosts. [Python SDK](https://github.com/temporalio/sdk-python), [activity idempotency and retries](https://docs.temporal.io/activity-definition), [cancellation reproducer](https://github.com/temporalio/sdk-python/issues/700).

## Observation, UI and evaluation evidence

- WebArena's ICLR 2024 study reported 14.41% for its best GPT-4-based configuration and 78.24% for human participants. Those figures describe its benchmark and historical model setup. The 2026 BreakingWeb preprint adds controlled changes to otherwise equivalent tasks. Its authors report materially lower success after interventions, which supports testing stale selectors, modified forms, navigation, and changed page state on resumption. [WebArena](https://webarena.dev/), [WebArena paper](https://openreview.net/pdf/384c500abb2b5adc4f3c40956a267477925c4b94.pdf), [BreakingWeb](https://arxiv.org/abs/2609.35814).
- Probe to Act's September 2026 preprint reports a VisualWebArena improvement from 54.1% to 61.2% in its Gemini-3-Pro configuration, with roughly 1.2 times the peak retained context of action-only history in its comparison. Its evidence supports measuring selective visual probes rather than assuming a screenshot in every prompt is best. Compare bounded accessibility/DOM context, screenshot-on-demand, and richer history on the same benchmark. Collect completion, wrong-target actions, model token counts, and end-to-end time. [Probe to Act](https://arxiv.org/abs/2609.33646), [VisualWebArena](https://arxiv.org/abs/2401.13649).
- Mind the Web demonstrates indirect prompt injection against browser agents operating with powerful tools. Treat website content as data. Check scope, input and approval at dispatch even when the model interprets a page differently. The paper’s results concern its selected agents, versions, and attacks. [Mind the Web](https://arxiv.org/abs/2506.07153).
- Browserbase Live View centers a single browser and exposes a clear control affordance. DevTools supports docking while preserving page visibility. The workspace uses a primary browser pane and keeps conversation and activity in the same side rail. A stacked layout retains both on narrow screens. A full-width timeline would hide the browser during inspection, while three permanently visible columns would consume width for scrolling and make browser targets smaller. [Browserbase Live View](https://docs.browserbase.com/features/session-live-view), [Chrome DevTools placement](https://developer.chrome.com/docs/devtools/customize/placement), [interaction-driven browsing paper](https://arxiv.org/abs/2509.12049).
- Hacker News launch discussions supplied practitioner reports on accessibility-tree grounding and maintainer rationale for keeping step control in application code. Reddit threads supplied anecdotes about brittle production automation and workflow side effects after resumption. They suggest edge cases and test scenarios. They do not rank the tools by reliability. Indexed X searches returned no substantive, verifiable engineering report used for this decision. [Browser Use discussion](https://news.ycombinator.com/item?id=43173378), [Stagehand discussion](https://news.ycombinator.com/item?id=42635942), [production automation thread](https://www.reddit.com/r/AI_Agents/comments/1slvuta/stagehand_vs_browser_use_which_one_actually_works/), [resume side-effects thread](https://www.reddit.com/r/LangChain/comments/1wppy9n/checkpointer_vs_durable_execution_for_prod/).

GitHub metadata, release pages, source files and selected issue/discussion threads were sampled. GitHub's API rate limit blocked some recursive-tree and fork exploration. No hosted products or third-party benchmark deployments were run for this section. The repository's local test and performance results are reported separately. Revisit the decision if same-fixture runs show weak completion despite reliable ownership, or if multi-worker recovery becomes a near-term requirement.
