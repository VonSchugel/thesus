# Reverse-engineering ecosystem evidence

Reviewed November 6, 2026 for THESUS. Source inspection, maintainer reports, community accounts, and local execution are labeled separately. The [source registry](reverse-engineering-sources.json) records the examined versions, evidence and decisions. The [integration decision](reverse-engineering.md) weighs the alternatives against the workspace's host and trust model.

## REA, leanrea and ERA

**REA upstream.** The Node/TypeScript system grew into a tool and evidence orchestration layer across disassemblers, package parsers, browser/Electron observations and retained captures. The CLI package, `rea-agents`, and MCP transport expose capabilities with different provider and host prerequisites. At the inspected source revision, `EvidenceMcpServerCore` composes request processing, the Ghidra provider has separate client and capability interfaces, and the retained-application test exercises references within an MCP connection. The JavaScript path builds an inventory, parses files, constructs application and semantic graphs, and retains coverage, locations and limitations. The shipped `6.8.0` CLI returned distinct raw and normalized results, provider identity, evidence links and hashes when run locally against the self-authored fixture. Native providers and desktop/runtime tool availability were assessed from source and docs. REA is MIT. Commercial providers still require their own licenses and access. [Source revision](https://github.com/morluto/rea/tree/a93eb39698e6aa2cec86e26e7e9a4b74d3d7a6c2), [MCP composition](https://github.com/morluto/rea/blob/a93eb39698e6aa2cec86e26e7e9a4b74d3d7a6c2/src/server/EvidenceMcpServerCore.ts), [Ghidra client](https://github.com/morluto/rea/blob/a93eb39698e6aa2cec86e26e7e9a4b74d3d7a6c2/src/ghidra/GhidraProviderClient.ts), [retention test](https://github.com/morluto/rea/blob/a93eb39698e6aa2cec86e26e7e9a4b74d3d7a6c2/tests/boundary/mcp/retainedApplicationEvidenceMcp.test.ts), [shipped package](https://www.npmjs.com/package/rea-agents/v/6.8.0)

**leanrea.** This is an independent CLI-first skill and experiment harness. The reviewed tree contains guidance, runner and data. It delegates analysis to preexisting utilities instead of shipping a tool server or its own evidence store. Its maintainer's matched comparison used macOS arm64, one model and host harness, four tasks and three runs per arm per task. They report 388 seconds and 74/75 answers for leanrea, 627 seconds and 75/75 for REA with its skill and MCP surface. One bare-model task refusal and a corrected regex-grader false negative illustrate the importance of reviewing failures. The comparison favors smaller prompt/tool exposure on those tasks and leaves Windows cost, authority enforcement and durable recovery unmeasured. Transfer the small menu and use the non-agentic baseline. [Skill source](https://github.com/aicodeking/leanrea/blob/09ba4aa0217f82cd880f855a60b877f59f39b22b/leanrea/SKILL.md), [benchmark and raw methodology](https://github.com/aicodeking/leanrea/blob/09ba4aa0217f82cd880f855a60b877f59f39b22b/bench/BENCHMARK.md)

**ERA Agent.** The pinned source is a separate REA-derived integration. `ReaClient.run` resolves a CLI, runs a structured subcommand, captures progress separately, and retains the output and metadata under a run directory. `ProjectStore` persists project and run JSON and exposes resumable statuses. Candidate work passes through a workspace policy and isolation selection. The additions are a persisted multi-step project lab, reviewer/candidate handoff and approval-oriented improvement workflow. These are substantive extensions beyond the underlying tool invocation. Environment scrubbing in a child process and platform-dependent sandbox selection have different guarantees. Use an explicit artifact and investigation ledger. Defer self-modification and candidate execution to a distinct sandboxed evaluation project. [REA client](https://github.com/dav1dngy/era-agent/blob/68ad521eb5036d6731d6a373f625a6e6f3e40658/src/rea_integration/rea-client.js), [project store](https://github.com/dav1dngy/era-agent/blob/68ad521eb5036d6731d6a373f625a6e6f3e40658/src/project_lab/store.js), [candidate boundary](https://github.com/dav1dngy/era-agent/blob/68ad521eb5036d6731d6a373f625a6e6f3e40658/src/safety/candidate-sandbox.js), [license and upstream notices](https://github.com/dav1dngy/era-agent/blob/68ad521eb5036d6731d6a373f625a6e6f3e40658/THIRD_PARTY_NOTICES.md)

## Engines and forks

| Technology | What the implementation offers | Scope and decision |
| --- | --- | --- |
| Capstone, pefile and pyelftools | A compact instruction decoder and two format readers. pefile's fast-load path exposes headers without walking all data directories. pyelftools supplies ELF program headers and segments. THESUS bounds decoding to file-backed executable bytes and retains source locations. | **Integrate.** Provides static evidence at low startup cost. Stripped function boundaries, program semantics and runtime behavior need other methods. [Capstone Python binding](https://github.com/capstone-engine/capstone/tree/5.0.9/bindings/python), [pefile 2024.8.26](https://github.com/erocarrera/pefile/blob/v2024.8.26/pefile.py), [pyelftools 0.33](https://pypi.org/project/pyelftools/0.33/) |
| LIEF and LLVM | LIEF provides one C++-backed binary parser across several formats and can modify supported images. LLVM's object and MC libraries underpin established toolchain disassembly. | **Study.** Evaluate LIEF for Mach-O and broad format needs, and LLVM for architecture parity or differential decoding. Keep mutation out of an inspection adapter. Cross-language packaging and native parser exposure still need testing. [LIEF source](https://github.com/lief-project/LIEF/tree/main/src), [LLVM object sources](https://github.com/llvm/llvm-project/tree/main/llvm/lib/Object) |
| Ghidra, PyGhidra and GhidraMCP | Headless Ghidra imports targets, creates projects and runs timed analyzers or scripts. PyGhidra exposes the Java engine to Python. GhidraMCP exposes named analysis and annotation tools. Its v2 release distinguishes headless use from the earlier GUI/bridge architecture. A separate Ghidra MCP implementation also exposes debug and mutation surfaces. | **First deeper native candidate.** Run a per-investigation private project on a pinned supported Ghidra/JDK in an isolated worker. Approve a subset of read operations and reject annotation or debugger actions in a static profile. [Ghidra 12.1.3 headless runner](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/RuntimeScripts/support/analyzeHeadlessREADME.md), [GhidraMCP release history](https://github.com/LaurieWired/GhidraMCP/releases), [separate bridge source](https://github.com/bethington/ghidra-mcp/tree/main/src/main/java) |
| IDA and Binary Ninja | IDA's MCP implementation exposes function analysis, supports an attached IDB and newer headless workflows, and can offer mutating functions. Binary Ninja exposes BinaryView and several intermediate languages through a published API. The respective analysis engines are proprietary. | **Optional bring-your-own adapters.** Require entitlement, pin engine/bridge compatibility, distinguish owned from caller-owned sessions, and bind inputs by digest. Never equate a loopback MCP port with read-only isolation. [IDA bridge sources](https://github.com/mrexodia/ida-pro-mcp/tree/main/src/ida_pro_mcp), [Binary Ninja IL API](https://docs.binary.ninja/dev/bnil-overview.html), [Binary Ninja API source](https://github.com/Vector35/binaryninja-api/tree/dev/python) |
| radare2, r2ai, Rizin and Cutter | radare2 uses a command-driven core and plugins. r2ai's agent mode routes analysis calls through that core and adds model-backed interpretation. Rizin is a substantive fork. Its v0.9 releases consolidate architecture plugins and advance RzIL, while keeping compatibility during parts of the migration. Cutter provides a GUI and plugin ecosystem over Rizin. | **Study.** A bounded JSON command profile and isolated owner process are a credible alternative to a Java worker. Avoid shell strings and broad command access. Test JSON fields, control-flow recovery and the same fixture set before deciding. [r2ai implementation](https://github.com/radareorg/r2ai/tree/master/src), [Rizin lineage](https://rizin.re/posts/announcing-rizin/), [Rizin v0.9.0](https://github.com/rizinorg/rizin/releases/tag/v0.9.0), [Cutter](https://github.com/rizinorg/cutter) |
| Tree-sitter, ASAR and Electron | The Tree-sitter JavaScript grammar emits syntax trees without running target code. Electron documents ASAR as its packaging format and defines contextBridge and paired invoke/handle calls. REA's worker-based JavaScript path adds source-map and semantic graph coverage. | **Integrate narrow syntax inspection.** Support single JS and bounded ZIP members today. Trial ASAR through the official reader or REA on a fixture with source maps, unpacked sidecars and ambiguous channels. [Tree-sitter parser API](https://github.com/tree-sitter/py-tree-sitter/tree/v0.25.2), [JS grammar](https://github.com/tree-sitter/tree-sitter-javascript/tree/v0.25.0), [Electron ASAR](https://www.electronjs.org/docs/latest/tutorial/asar-archives), [IPC](https://www.electronjs.org/docs/latest/tutorial/ipc) |
| JADX and Android tooling | JADX's Java core loads DEX and related containers, produces source-like output, and supports plugins. APK contents, DEX, manifest, signatures and embedded native libraries are distinct analysis subjects. | **Defer deep mobile.** Begin with ZIP inventory and then separately validate JADX against a self-built APK and an expected method call. Treat decompiler errors and missing classes as coverage gaps. No device is needed for static tests. [JadxDecompiler source](https://github.com/skylot/jadx/blob/master/jadx-core/src/main/java/jadx/api/JadxDecompiler.java), [release history](https://github.com/skylot/jadx/releases) |
| ILSpy and managed Windows | ILSpy includes `CSharpDecompiler` plus a CLI over managed metadata and IL. NativeAOT, mixed-mode images and packed .NET apps require separate detection and engine selection. | **Defer managed decompilation.** Report CLR-directory presence without asserting recovered C# or absence of native code. Trial ILSpy on a compiled assembly with generic and async fixtures. [CSharpDecompiler](https://github.com/icsharpcode/ILSpy/blob/master/ICSharpCode.Decompiler/CSharp/CSharpDecompiler.cs), [ILSpy releases](https://github.com/icsharpcode/ILSpy/releases), [PE directory format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format) |
| Binwalk and Unblob | Binwalk v3 is a Rust signature and extraction tool. Unblob's handlers identify chunk boundaries and may invoke extraction tools, with recursion and path containment considerations. Raw firmware regions, a loadable ELF and a mounted filesystem are different evidence types. | **Study in a Linux sandbox.** A self-compiled freestanding ELF is the current embedded oracle. A real firmware lane needs bounded carving, no mounting or execution, auditable offsets and an extraction-boundary attack suite. [Binwalk v3 code](https://github.com/ReFirmLabs/binwalk/tree/master/src), [Unblob handlers](https://github.com/onekey-sec/unblob/tree/main/unblob/handlers), [Unblob deployment docs](https://unblob.org/) |
| Wireshark/TShark, HAR, Frida and CDP | TShark can decode offline packet captures through registered dissectors. HAR carries application-level exchanges, which can omit transport or timing evidence. Frida and CDP can instrument running authorized applications and produce runtime observations. Attaching, evaluating scripts and capturing a profile have different privileges. | **Integrate offline HAR comparison.** Future offline PCAP and passive trace imports need explicit input coverage and redaction. Keep live instrumentation, certificate changes and target launches in a separately authorized and isolated lane. [TShark source on GitLab](https://gitlab.com/wireshark/wireshark/-/blob/master/tshark.c), [HAR 1.2 format](http://www.softwareishard.com/blog/har-12-spec/), [Frida JS API](https://frida.re/docs/javascript-api/), [CDP Network domain](https://chromedevtools.github.io/devtools-protocol/tot/Network/) |

Use the original project's license and distribution terms for actual reuse. THESUS imports the pinned Python libraries and launches its own parser worker. It contains no copied third-party analyzer implementation. A CLI boundary simplifies updates and authority review, while redistribution obligations still depend on the tool and distribution.

## Program understanding, verification and autonomy

| Technique | Benefit, cost and acceptance test |
| --- | --- |
| Function identification and semantic recovery | Ghidra analyzers, Rizin lifters and library signatures can expand coverage beyond entrypoint bytes. Compiler settings, stripped names, code/data ambiguity and inlining make ground truth essential. Compare on build-separated stripped binaries with known boundaries. Record precision, recall and unresolved bytes before considering model-generated names. [REBENCH research and corpus](https://arxiv.org/abs/2604.27319), [Ghidra headless controls](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.1.3_build/Ghidra/RuntimeScripts/support/analyzeHeadlessREADME.md) |
| Symbolic execution, emulation and fuzzing | angr's simulation manager holds sets of states and applies exploration strategies. The solver and host call models can generate input witnesses, while branching, external calls and environment assumptions limit coverage. Start with one bounded function, fixed time/state budgets, and a compiled oracle. Confirm a generated witness independently. [angr simulation manager source](https://github.com/angr/angr/blob/master/angr/sim_manager.py), [symbolic execution examples](https://docs.angr.io/en/latest/examples.html) |
| Reconstruction, synthesis and differential testing | A plausible recompilation may still change behavior. Check observable outputs and state against independently authored inputs, including a deliberate mutation. DecompileBench demonstrates runtime-aware validation, while its automated assessments and harness are their own evidence type. Extend from HTTP fixture signatures to typed state transitions before testing general code synthesis. [DecompileBench paper](https://aclanthology.org/2025.findings-acl.1194/), [LLM4Decompile source](https://github.com/albertan017/LLM4Decompile) |
| Adaptive planning and specialized agents | r2ai and ERA illustrate routing between tools and specialized reasoning. Open-ended tool selection adds latency, prompt exposure and recovery complexity. Keep the deterministic inventory and parser baseline. Trial a bounded hypothesis proposer with evidence references and a tool budget. Assess false inference rate, verified completion and operator intervention on held-out fixtures before adding a second agent. [r2ai conference presentation](https://radare.org/get/r2ai-hackbcn2025.pdf), [ERA team source](https://github.com/dav1dngy/era-agent/blob/68ad521eb5036d6731d6a373f625a6e6f3e40658/src/agents/team.js) |
| Long investigations, evidence retrieval and replay | ERA run records and REA evidence graphs show two distinct layers. THESUS stores an immutable artifact, pinned plan, audit, evidence and inferred references. Begin with typed lookup and stable result IDs. Trial evidence paging, a graph projection and provenance-aware retrieval when one report exceeds the current budget. Verify copied and resumed runs preserve exact coordinates and never treat an unknown as an observed absence. |
| Independent agent benchmarks | AgentRE-Bench and SRE-Bench offer multi-step tasks and controlled artifact/oracle splits. Their tool budgets, formats, preprocessing and evaluation rules differ. Reproduce one authorized non-malware task per class with a fixed permission and budget matrix. Avoid merging model and parser timings or reading benchmark ground truth into the agent's input. [AgentRE-Bench inspected revision](https://github.com/agentrebench/AgentRE-Bench/tree/c0f5fa5b5c1447ce2cc764b96365bc9fed0cbf01), [SRE-Bench author page](https://daplab.cs.columbia.edu/benchmarks/sre-bench/) |

## Practitioner evidence and access limits

- The curated REA ecosystem index is a discovery source. Its case taxonomy distinguishes confirmed tool use from lookalike projects. The independent PlxNative repository documents an LG TV implementation and credits Ghidra and Claude Code. That supports the feasibility of a compatibility project with manual analysis, with no controlled REA attribution or timing conclusion. [Pinned index](https://github.com/AIshihzong/awesome-reverse-engineer-anything/tree/3e74bb397ee3a0352f851343ceafdd67f0906f32), [PlxNative](https://github.com/GLinnik21/plx-native)
- Public discussions surface practical failure modes. A Ghidra community report identified a decompiler buffer limit, and a Ghidra MCP developer described retaining oversized responses behind handles. These are self-reported examples. They motivate timeout, partial-coverage and large-output tests. [Ghidra decompilation report](https://www.reddit.com/r/ghidra/comments/1v73af7/why_is_ghidra_unable_to_decompile_a_function/), [MCP response-size discussion](https://www.reddit.com/r/ghidra/comments/1r3xaaj/ghidramcp/)
- The larger Hacker News discussion questions what broad target support means in practice. Its binary MCP launch thread supplies announcement context. An original X link returned HTTP 403, so the curated links remain leads. Codeberg was blocked by its search access rules, and private Discord material was outside the accessible corpus. GitHub source and release records, npm, PyPI, crates.io discovery, GitLab Wireshark source and public publications provide alternatives.
