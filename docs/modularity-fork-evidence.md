# THESUS browser integrations and fork evidence

Evidence snapshot from November 6, 2026. This study covers code lineage, the boundary between planning and dispatch, and concrete integration costs. **Source** denotes behavior visible in the cited revision. **Reported** denotes a maintainer, researcher, or practitioner account. **THESUS decision** denotes an inference from those findings and the current application. Package publication, branch activity, and production fitness are separate observations. The external implementations were inspected without executing them.

## Current extension boundary

THESUS already separates a model decision from a browser action. `BrowserPlanner` returns an `AgentDecision`. `LiveWorkspace._dispatch` passes a `BrowserCommand` and an expected revision to the browser. `PlaywrightAdapter.execute` checks that revision. The older `BrowserAdapter` protocol instead exposes `run_navigation_step` and `execute_action`, and the older `BrowserUseAdapter` installs a browser-use step callback. The application selects Playwright for live operation. A new integration needs to target the intended planner or live-driver boundary explicitly because implementing the older protocol alone gives it different lifecycle and authority. [Planner](../app/agents/browser_planner.py), [workspace dispatch](../app/core/live_workspace.py#L505), [Playwright revision check](../app/integrations/browser/playwright_adapter.py#L677), [older protocol](../app/integrations/browser/base.py#L12), [app wiring](../app/app.py#L43).

## Browser Use fork and approval coverage

**Source.** Upstream 0.13.14 accepts injected model, tools, and browser session objects. Its run loop calls step start/end hooks around a step, and `Agent.multi_act` dispatches a list of actions through `Tools.act` and its registry. Step lifecycle callbacks are useful for telemetry and supervision. The reviewed hook and dispatch paths place the tool registry and the browser within the framework's execution authority. [Upstream agent inputs](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/agent/service.py#L135-L185), [step hooks](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/agent/service.py#L2455-L2505), [batch execution](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/agent/service.py#L2755-L2816), [tools registry dispatch](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/tools/service.py#L2178-L2227).

**Source.** USE-IT introduces `interactive_mode`, a callback taking step metadata, model output, and a browser summary, and a typed decision covering approve, retry, skip, and cancel. In the interactive path `StepExecutor` waits for that callback and handles each decision before ordinary execution. A missing callback raises when the mode requests approval. The separate initial-actions method calls `multi_act` directly, and `AgentRunner.run` invokes that method. Approval in the reviewed path covers the model's proposed batch. Initial actions have a separate path and the callback API carries no durable browser lease or approval revision. These are concrete coverage boundaries when treating the fork as a reference for host enforcement. [Configuration](https://github.com/Mega-Gorilla/USE-IT/blob/8f779c945c8be90617992ae62e47da60d602d18e/browser_use/agent/config.py#L24-L71), [decision logic](https://github.com/Mega-Gorilla/USE-IT/blob/8f779c945c8be90617992ae62e47da60d602d18e/browser_use/agent/step_executor/service.py#L23-L122), [initial actions](https://github.com/Mega-Gorilla/USE-IT/blob/8f779c945c8be90617992ae62e47da60d602d18e/browser_use/agent/step_executor/service.py#L331-L355), [runner](https://github.com/Mega-Gorilla/USE-IT/blob/8f779c945c8be90617992ae62e47da60d602d18e/browser_use/agent/runner/service.py#L73-L96).

The fork's history separates three changes. It extracted a step executor on October 14, added interactive approval the following day, then replaced the CLI with a PySide6 GUI on October 16. THESUS can implement the approval boundary independently of either interface. [Step executor refactor](https://github.com/Mega-Gorilla/USE-IT/commit/ed1a5669887371e04bff0e51d46559d74a0bad43), [approval diff](https://github.com/Mega-Gorilla/USE-IT/commit/42bacc0d33d8dcdaf3648179e0ac40b37b6a8342), [GUI diff](https://github.com/Mega-Gorilla/USE-IT/commit/40c98e11b832c10019226f38029a55db4fba5f95).

**THESUS decision.** Carry the insertion point over as a host rule for every browser mutation. A decision applies to one canonical command, one browser revision, and one ownership epoch. Retry, skip, cancel, and edit map to typed workflow outcomes. An edit yields a fresh proposal. Test ordinary planning, initial commands, replay, automatic retries, manual takeover, and shutdown while waiting. Favor an upstream proposal-only API or a tightly scoped adapter. Maintaining the fork would bring an older dependency tree and ongoing merge, security, and regression work into the browser control path. The issue that surfaced the fork was opened in the upstream tracker by the fork author and redirected to the fork. It does not establish upstream acceptance or production use. [Issue and author clarification](https://github.com/browser-use/browser-use/issues/3341), [request about pausing mid-tool](https://github.com/browser-use/browser-use/issues/4798).

## Stagehand and the browser lifecycle

**Source.** Stagehand separates the SDK, browser extension, and wire schema. The v4 protocol README documents bidirectional JSON-RPC, one generated JSON Schema feeding language bindings, and a runtime protocol version separate from package releases. The Python connection layer distinguishes a browser launched by the integration from an attached or persistent browser. `disconnect()` waits for the extension's detach acknowledgement before closing the client. Initialization failure closes the client and closes the underlying browser source when owned. Its configuration notes say the disconnect watchdog requires Chrome 137 or newer, and reconnecting with an incompatible extension can require a new session or the original SDK version. [Wire contract](https://github.com/browserbase/stagehand/blob/5a5b48acfadf637f2243233745fc5fc277b89b34/packages/protocol/README.md#L1-L68), [Python connection lifecycle](https://github.com/browserbase/stagehand/blob/5a5b48acfadf637f2243233745fc5fc277b89b34/packages/sdk-python/src/stagehand/browser.py#L455-L523), [browser requirements](https://github.com/browserbase/stagehand/blob/5a5b48acfadf637f2243233745fc5fc277b89b34/packages/docs/v4/configuration/browser.mdx#L714-L775).

**Source and reported deployment.** Browserbase's Deep Agents example exposes `run`, `snapshot`, and `screenshot` through a separate tool facade and includes a registry that reattaches or releases old browser sessions and expires idle entries. This is inspectable adapter code. LangChain's managed product announcement describes a separate browser sandbox and human handoff. Its engineering writeup reports 90% success, 17.4 seconds median, and $1.98 total for the Stagehand toolset across 100 WebVoyager tasks with Claude Sonnet 5.5. The accompanying evaluation pull request shows that variants differed in browser location and transport in addition to tool surface. This is an adopter-run comparison on its chosen task sample and harness. It provides hypotheses about batching and compact observations for a THESUS experiment. [Example contract](https://github.com/browserbase/stagehand/blob/5a5b48acfadf637f2243233745fc5fc277b89b34/packages/integrations/deepagents/README.md#L73-L105), [session registry](https://github.com/browserbase/stagehand/blob/5a5b48acfadf637f2243233745fc5fc277b89b34/packages/integrations/deepagents/examples/managed/tools/stagehand.py#L173-L235), [deployment](https://www.langchain.com/blog/browser-use-in-managed-deep-agents), [results](https://www.langchain.com/blog/how-we-optimized-browser-use-for-deep-agents), [evaluation PR](https://github.com/langchain-ai/deepagents/pull/6868).

**THESUS decision.** Start with Stagehand observations on disposable sessions if the existing planner needs better grounding. Translate candidate targets into host-owned references and revalidate them immediately before dispatch. The Deep Agents facade's `run` accepts either batches or JavaScript, which is broader authority than the proposed observation adapter. Keep policy enforced at the browser/network boundary. A reported v4 policy bypass via service workers or WebSockets and a Windows headless Chrome shutdown report against TypeScript 4.2.1 supply targeted regression cases. Their reproductions were not rerun against 4.4.0 for THESUS. Additional costs include Chrome and the extension, protocol upgrade compatibility, browser RAM, possible cloud sessions, and controls for who can use the CDP endpoint and retained profile. Benchmark SDK and extension overhead separately from model time. [Domain policy report](https://github.com/browserbase/stagehand/issues/2945), [Windows shutdown report](https://github.com/browserbase/stagehand/issues/3166).

## AutoGen, MagenticLite, and AG2

- **Microsoft AutoGen, source.** `SingleThreadedAgentRuntime` supports factory registration, persisted agent state, and asynchronous envelope processing with `create_task`. The single event loop can still interleave handlers. Magentic-One's specialized browser, file, and code agents are assembled under an orchestrator whose task and progress ledgers can trigger replanning. This is a reference for bounded replanning and separate operational events. THESUS should still serialize writes to each externally mutable resource and treat replanning as a new plan revision. [Runtime](https://github.com/microsoft/autogen/blob/83afbf5857aac683340d4c692194e548b1e8edda/python/packages/autogen-core/src/autogen_core/_single_threaded_agent_runtime.py#L149-L186), [message dispatch](https://github.com/microsoft/autogen/blob/83afbf5857aac683340d4c692194e548b1e8edda/python/packages/autogen-core/src/autogen_core/_single_threaded_agent_runtime.py#L711-L791), [Magentic-One paper](https://www.microsoft.com/en-us/research/wp-content/uploads/2024/11/Magentic-One.pdf).
- **Magentic-UI to MagenticLite, source.** The 0.1.6 package pins AutoGen AgentChat/Core/Extensions 0.5.7. At 0.2.1 those dependencies are absent from the package manifest and the redesigned app lists Quicksand packages. A config selector enables both agent roles or only one. The Quicksand browser manager acquires and releases browser slots and starts Chromium, a dedicated display, and noVNC inside a VM. The reviewed Fara adapter saves a local JSON record of conversation and selected browsing state, which illustrates why replayable workflow records need to stay separate from a live browser instance. The VM is a useful candidate when THESUS needs browser or code isolation strong enough to justify image, boot, port, network, and cleanup costs. Microsoft calls MagenticLite experimental and describes browser screenshots reaching configured model providers. [0.1.6 dependencies](https://github.com/microsoft/magentic-ui/blob/v0.1.6/pyproject.toml#L27-L34), [0.2.1 dependencies](https://github.com/microsoft/magentic-ui/blob/edf985946db448df3b0d3a2bd0bd3492664972c2/pyproject.toml#L27-L54), [role configuration](https://github.com/microsoft/magentic-ui/blob/edf985946db448df3b0d3a2bd0bd3492664972c2/docs/configuration.md#L88-L139), [browser pool](https://github.com/microsoft/magentic-ui/blob/edf985946db448df3b0d3a2bd0bd3492664972c2/src/magentic_ui/tools/playwright/browser/quicksand_browser_manager.py#L187-L339), [Fara state](https://github.com/microsoft/magentic-ui/blob/edf985946db448df3b0d3a2bd0bd3492664972c2/src/magentic_ui/agents/web_surfer/fara/_fara_web_surfer.py#L193-L259), [transparency note](https://github.com/microsoft/magentic-ui/blob/main/docs/TRANSPARENCY_NOTE.md).
- **AG2 Classic to 1.3, source.** Classic retains `ConversableAgent` with reply hooks and modes for asking the human at conversation boundaries. The newer `ag2.Agent` API uses explicit worker delegation via `as_tool()` and accepts plugin objects whose contributions include tools, prompts, middleware, observers, and human hooks. AG2 1.3 introduces copied, local, and explicitly shared variable scopes. Descendant observations can reach ancestors without being inserted into model context. The release notes assign synchronization of shared values to the application and explain that handles for live child invocations expire and cannot be used on replay. Transfer copied inputs by default, explicitly shared resource capabilities, typed observation events, and separate stable IDs versus live handles. The API split, deprecations already scheduled for 1.4, and Python 3.11 floor reinforce the value of an optional wrapper over framework classes in persisted state. AG2 Classic's package metadata and PyPI artifact confirm the package name `autogen`; verify package identities instead of relying on naming in migration examples. [Classic reply hooks](https://github.com/ag2ai/ag2-classic/blob/86fa5ccb3f9424cee87edb4a9ea58f191ea958ba/autogen/agentchat/conversable_agent.py#L561-L600), [Classic package metadata](https://github.com/ag2ai/ag2-classic/blob/86fa5ccb3f9424cee87edb4a9ea58f191ea958ba/pyproject.toml#L33-L45), [AG2 plugin composition](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/plugin.py#L221-L355), [worker delegation](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/agent.py#L1974), [scoped variables](https://github.com/ag2ai/ag2/blob/1229064a23a1e39a4c3c089bb4643a637117c8a9/ag2/scopes.py#L21-L93), [1.3 release details](https://github.com/ag2ai/ag2/releases/tag/v1.3.0).
- **Microsoft Agent Framework, source.** A merged October 2026 PR added optional asynchronous chat-client context management and provider-aware disposal. The base closes via the context exit hook and provides a no-op default. Provider implementations close connections they own and preserve externally supplied clients according to the PR's lifecycle contract. This is a useful implementation pattern for injected THESUS resources. The same release reports a breaking Redis context index change requiring re-ingestion. Keeping framework-native persistence behind an adapter makes such schema upgrades local to the provider. [BaseChatClient lifecycle](https://github.com/microsoft/agent-framework/blob/43d767c55050480e470ebf0a89caa4141d325ebf/python/packages/core/agent_framework/_clients.py#L322-L346), [implementation PR](https://github.com/microsoft/agent-framework/pull/9748), [1.24.0 release notes](https://github.com/microsoft/agent-framework/releases/tag/python-1.24.0).

## Trial and removal criteria

1. **Run a matched grounding comparison.** Compare the existing Playwright observation and planner to a Stagehand observation or a Browser Use proposal adapter using identical local sites, model, token and action budgets, seeded browser state, and privacy policy. Include accessibility gaps, frames, and stale selectors. Measure completion, wrong targets, p50/p95 latency, model tokens, and process/browser memory. Record browser initialization separately from repeated calls.
2. **Prove the authority boundary.** Kill the worker before dispatch, after dispatch and before result persistence, and during detach. Attempt a stale approval after manual takeover or a reconnected browser. Exercise browser-generated egress through service workers and WebSockets. Count unauthorized or duplicate effects. Require zero of either before exposing a mutating integration and send uncertain external outcomes for reconciliation.
3. **Prove removal with a live reference.** Run provider A and substitute B for a new run using the same host contract. Pin or drain A for its active run and pending approval. Verify the old run and events remain inspectable after removing A, old authority cannot be reused, and A-owned sessions and credentials are revoked or disposed. Verify a browser attached by the caller stays available according to its owner policy. Test the rollback path before widening use.
4. **Prefer upstream changes over carrying a fork.** Use a public proposal, observation, or lifecycle seam if available. Submit a minimal upstream hook with a reproducible invariant and tests when that seam is missing. A temporary pinned fork needs an owner, a bounded delta, a supported upstream rebase target, a patch sunset condition, and separate policy conformance tests. Preserve license notices and verify file-level and bundled-component terms before adapting code. Model weights, images, and hosted services can have separate terms.

The 2025 Hacker News launch threads supplied two testable leads. The Stagehand maintainer argued for retaining deterministic, code-defined control over steps. A Browser Use commenter reported that accessibility data could suffice on well-structured sites. Both describe historical experience and suggest including poorly labeled sites and deterministic fixtures. A separate ICLR 2026 workshop comparison documents varying WebVoyager task counts and scoring conventions across published results. Indexed X searches did not yield a usable engineering demonstration for this comparison, and a linked AG2 announcement returned a 403. GitHub API rate limits prevented exhaustive fork-tree inspection. Pinned files, package metadata, and maintainers' release notes support the decisions here.
